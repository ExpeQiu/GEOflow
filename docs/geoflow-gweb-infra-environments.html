基于同机部署基线（Compose · Nginx · PG/pgvector · Redis/Celery），给出 DEV / TEST / UAT / 生产 各维度可落地的规格、端口、资源 limit、参数与环境变量。 数值为建议起点，可按探针题量与 chunk 规模上浮。

3.2 启动命令（生产形态）

API / Content Worker

uvicorn app.main:app \
  --host 0.0.0.0 --port 8080 \
  --workers 2
# 禁止生产 --reload

celery -A app.workers.celery_app worker \
  -Q celery,geoflow \
  --concurrency=2 \
  --loglevel=info \
  --max-tasks-per-child=50

Batch Worker / Beat

celery -A app.workers.celery_app worker \
  -Q batch \
  --concurrency=1 \
  --loglevel=info

celery -A app.workers.celery_app beat \
  --loglevel=info
# 全环境仅 1 个活跃 Beat
健康检查：API GET /health · Gweb GET /api/health · PG pg_isready · Redis PING。 Compose depends_on + interval 10s / retries 10（与现仓库一致）。

    listen 443 ssl http2;

七、NAS 详细配置

7.1 何时需要 / 挂载点
环境NAS容量建议协议
DEV/TEST不需要（本地 volume）——
UAT可选预演50GBNFS v3/v4
生产 · Gweb 多副本 必挂 100GB 起 · 按 MDX 增长 NFS；性能型
生产 · 单机 Gweb不强制本地盘 + OSS 备份—
挂载路径（容器内）宿主机/NAS 路径读写方
/app/content/wiki（Gweb） /mnt/nas/gweb/content/wiki wiki/sync 写入 · 页面读取
/app/storage/uploads（API+Worker） /mnt/nas/geoflow/uploads 或改 OSS 多 Worker 共享时需要
PG data 禁止挂 NAS；用云盘或 RDS 
# 宿主机 fstab 示例
<nas-addr>:/gweb-wiki  /mnt/nas/gweb/content/wiki  nfs  vers=4,rsize=1048576,wsize=1048576,_netdev  0  0
未挂 NAS 前不要把 Gweb replicas 调到 >1，否则 /api/wiki/sync 只落单 Pod，页面出现「有时有、有时无」。

十、RocketMQ / 消息队列

10.1 现行与可选
环境方案配置要点
全部（现行） Celery + Redis Broker db0 · Result db1
队列：celery · geoflow · batch
关键任务：process_geoflow_task · evaluate_article · process_article_distribution · sync_knowledge_chunks · run_monitor_scan 等
DEV/TEST/UAT 不部署 RocketMQ 平台清单填写「Redis（Celery）」
生产（企业强制 MQ 时） 可选演进 独立 Topic 建议（若改造）：
GEO_CONTENT_TASK · GEO_EVAL · GEO_DISTRIBUTE · GEO_MONITOR_BATCH
需单独开发桥接；同机基线不含。上线不阻塞。
不建议 DEV 上 RocketMQ、生产上 Celery 双栈并存。统一以 Redis 队列验收，RocketMQ 仅作二期。
