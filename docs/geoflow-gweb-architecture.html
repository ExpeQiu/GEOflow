GEOFlow & Gweb 技术架构

GEO 技术品牌双系统：GEOFlow 负责内容生产、门禁与分发编排； Gweb 负责公网 Wiki 展现、Schema / llms.txt 与 AI 可引用面。 二者通过 Wiki Sync 契约解耦，无 monorepo 依赖。

GEOFlow v3 · FastAPI + Celery + LangGraph Gweb · Next.js 16 Presentation Agent-First · Clarify→Plan→Execute→Review PostgreSQL + pgvector / MDX SSOT

业务三层（GEOFlow）与主数据流

L2 内容生产（备料）

  • 知识库 / 素材 / Prompt
  • AI 模型配置 · RAG
  • 技术 IP 资产卡

L3 运营主链路（执行）

  • Task → Generate → Eval
  • Publish → Distribute
  • 技术品牌模式：仅 Gweb

L1 策略洞察（大脑）

  • 探针扫描 · 可见性 KPI
  • 采纳聚合 · 告警
  • 反哺 Prompt / 知识库
Beat 调度 Task → Worker 执行 → RAG 召回 + LangGraph 生成 → evaluate_article 门禁 → publish → GwebWikiPublisher → wiki/sync 写 MDX → revalidate + ai-submit → AI 引擎可引用

GEOFLOW_TECH_BRAND_MODE=true 时 Wiki 走 distribution_only → Gweb，不发本站前台。 溯源字段：geo_flow_task · geo_content_hash · source=geoflow。

数据架构图

GEOFlow DB · PostgreSQL

业务真相源：任务 / 文章 / 分发 / GeoEval / 鉴权。独立库，SQLAlchemy + Alembic。

向量 · pgvector

仅 knowledge_chunks.embedding_vector（3072 维）。RAG 召回落库，非独立向量库。

Redis · 队列态

Celery broker db0 + result db1。无业务自定义 key 缓存层。

Gweb Wiki · MDX 文件 SSOT

content/wiki/{type}/{slug}.mdx 不进 Prisma。溯源 frontmatter 由 sync 写入。

Gweb DB · gweb_db

Prisma：Document / Technique / Page / 媒体 / 用户。与 Wiki 文件平行，互不替代。

上传 / 媒体

GEOFlow storage/uploads；Gweb 媒体可走 COS / Techstore 反代。
