1.
包含哪些敏感数据，敏感数据量级（如 10 万条），上下游系统？
凭证：admins.password（bcrypt）· api_access_tokens.token_hash · distribution_channel_secrets · ai_models.api_key（支持 enc:v1）· .env 中 GWEB_* / DOUBAO_* / DEEPSEEK_* 等。
业务内容：knowledge_chunks 原文、articles / Wiki MDX、tech_ip_assets、geo_monitor_probe_results、可见性报告。
量级：随租户而定；探针题库约数百～数千题/品牌；知识切片与文章常见万级以内（按部署实测填数）。
上下游：见上图。
2.
前端是否脱敏，后端是否加密？
已做：Admin 密码 bcrypt；API Token 仅存 hash + prefix；渠道密钥 rotate + secret_hash；JWT；AI Key 支持 enc:v1 AES-GCM。
部分：渠道密钥录入为密码框；Token/密钥列表不回显全文。
缺口：业务正文库内默认明文；无系统级字段脱敏组件。
3.
数据采集、传输、存储、处理、交换、销毁各环节的安全保护措施？
采集：JWT / API Token scope；敏感词表。
传输：生产应强制 HTTPS；出站 Bearer；X-Request-Id。
存储：凭证哈希/可选 enc；本地 upload_path（非默认公有 OSS）。
处理：Celery · LangGraph · GEO 门禁 / Wiki 合规。
交换：wiki/sync + 溯源；渠道密钥隔离；idempotency。
销毁：Token revoke；secret rotate；文章 trash。
缺口：保留期与硬删除 Runbook 未成文；LLM Key UI 轮换未全覆盖。
4.
后台是否有数据导入导出编辑功能，是否有细粒度权限控制、完整的操作日志？
有：知识/素材/URL 导入、文章编辑、分发配置、TJG 导入、批量操作。
权限：admin / super_admin + Token scopes；尚无字段级 RBAC。
日志：admin_activity_logs（部分写操作）· request_id。
缺口：导出审计与全量操作落库未强约束。
5.
是否有数据跨境流动场景？请描述业务场景及具体字段。
可能有（取决于 Provider 机房）：出站 Prompt / RAG 片段 / 草稿 → LLM；问题文本 / 品牌名 → 探针 API；入站回答原文写回 geo_monitor_probe_*。境外 Provider 即构成跨境。
6.
如果使用了对象存储 OSS，是否包含敏感信息？（补充：后续会要求开数据库只读账号做分类分级）
默认不用公有 OSS：上传写入 UPLOAD_PATH（默认 ./storage/uploads）。若改为 S3/MinIO，对象可能含配图与知识附件（业务敏感）。分类分级只读账号应覆盖 tasks / articles / knowledge_chunks / geo_monitor_probe_results；凭证明文列禁止暴露。
证据：core/security.py · api_key_crypto.py · settings_crud_service.py · distribution_channel_secrets · gweb-integration.md · upload_path
