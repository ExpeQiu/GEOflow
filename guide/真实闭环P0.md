# 真实闭环（P0）落地说明

> 更新：2026-07-14  
> 目标：把「缺口看见 → 建 Task」补成「发布 → 再扫 → lift 可证明」，并堵住探针/RAG 造假。

---

## 闭环路径

```
场景缺口高 → 一键创建 Task（同步创建 remediation 实验）
    → 生产/审核/发布 → Gweb 分发成功
    → status=awaiting_rescan（默认 T+72h）
    → Celery process_due_remediations / 手动 rescan
    → 同 scene 再探针 → delta_visibility_pct
    → 诊断报告「闭环验证」章节
```

并行回流：`GET Gweb /api/pages.json` → Strategy Overview 对齐率。

## 关键配置（探针设置 UI / site_settings）

| Key | 建议生产值 | 作用 |
|-----|-----------|------|
| `monitor_probe_mode` | `api` | 真实 Chat API |
| `monitor_platforms` | `doubao,deepseek` | 已接 API 的平台 |
| `monitor_strict_api` | `true` | **禁止** api→llm/corpus 静默降级 |
| `remediation_delay_hours` | `72`（联调可 `0`） | 发布后再扫延迟 |
| `gap_rag_score_threshold` | `0.3` | RAG 判「有支撑」的分数线 |
| `AI_MOCK_MODE` | `false` | 关闭假 embedding |
| `DEEPSEEK_API_KEY` / `DOUBAO_*` | 必填 | 真实探针 |

迁移：`alembic upgrade head` → **`013_probe_parser_v2`**（含 012 补缺实验表）

外部 CLI（RAG / Sim / content-lg）为**可选外挂**，闭环不依赖它们；见 [cli-plugins.md](./cli-plugins.md)。

### 发布前 GEO 仿真（方案 A · 软门禁）

生产/审核后仍走 `evaluate_article`（RAG 模拟 + 审计 + 可选 Wiki 检查），但默认 **只写评分与建议**：

| 配置 | 默认 | 行为 |
|------|------|------|
| `GEO_EVAL_HARD_GATE` | `false` | 阈值未过 → `eval_status=advisory`，**不拦** publish / 自动分发 |
| 同上为 `true` | — | 未过 → `failed`，`ArticlePublishService` 拦截 |

文章编辑页与 Strategy GEO 面板展示 `simulation_score` + `recommendations`；真值 lift 仍靠发布后再扫。

## 数据口径（重要）

1. **Open-API 可见性** ≠ 豆包/元宝 App 联网搜索结果；strict_api 保证报告不被 corpus 污染。
2. **corpus citation** 仅当 `engine=corpus` 才落库，避免假「AI 引用了 Wiki」。
3. **缺口双通道**：已发布语料关键词 OR RAG `score≥阈值`；`source=fallback` 不算支撑。
4. **lift** 按 `scene_id` 问题子集对比，不用全站 visibility。
